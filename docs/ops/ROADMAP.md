## 二、已知限制（必须知道）

### 1. 数据口径

- 解读是**本命盘视图**：不含按当前年龄改写的句子、倪师法则附加段、AI 解读
- 按时辰序号直接排盘，**未做出生地真太阳时校正**（数据集本身如此）
- v4.0 是按旧默认「现代修正 v2」生成的，而引擎现在默认「斗数全书」——
  **亮度字和少量随亮度变化的解读句会与新默认不同**

### 2. 许可边界

| 内容 | 协议 | 商用 |
|---|---|---|
| 代码 | MIT | ✅ |
| 解读数据集 v4.0 | CC BY 4.0 | ✅（需保留来源标注） |
| 古籍原文 | 公有领域 | ✅ |
| 倪师《天纪》原话 | CC BY-NC-SA 4.0 | ❌ |

> 数据集解读里引用的倪师原话**不在数据授权范围内** —— 全球化对外销售前，
> 这一条必须先和法务确认边界。

### 3. 引擎/前端缺口

上游不开源的部分，需要我们自己实现：

| 缺口 | 影响 | 优先级 |
|---|---|---|
| `/api/interpret` AI 解读接口 | 前端「追问」功能不可用 | P0（商业化核心） |
| 商业级前端（上游 1227 行的排盘页 vs 我们 75 行） | 体验落后 | P1 |
| 用户系统（登录/会员/支付） | 无法收费 | P1 |
| 防刷/签名/水印 | 上线前必须 | P1 |
| 多语种（英/西/日/韩…） | 全球化 | P2 |

## 三、下一阶段建议

### 阶段 A：把「输入输出」做成可交付的产品形态（1–2 周）

1. **AI 解读接口**：用 `/api/interpret` 封装 LLM，prompt 走 `lib/ziwei/patterns.ts` + `heming-knowledge.ts`
   —— 这是唯一挡在「能卖」前面的技术缺口
2. **国际化闭环**：首页 + 命盘页 + 解读面板全英文，术语表对齐（14 主星 / 12 宫 / 13 维）
3. **SEO 基础**：英文站独立路由 + hreflang + 结构化数据（Person / Article）

### 阶段 B：商业化基建（2–3 周）

4. 用户系统 + 命盘历史（Postgres 已有 `ziwei_charts`，加 user_id 即可）
5. 支付（Stripe / Paddle）
6. 分享卡片 + 社交传播（命盘链接已可分享，直接接 OG 图）
7. 限流与防刷

### 阶段 C：增长（持续）

8. 英文 SEO 内容站（14 主星 × 12 宫 × 13 维 = 2,184 个落地页）
9. 多语种扩展
10. 命盘对比/合盘（引擎已支持 `heming-knowledge.ts`）
